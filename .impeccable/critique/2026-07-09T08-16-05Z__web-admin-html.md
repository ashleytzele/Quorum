## Anti-Patterns Verdict — PASS (clean)
LLM review + deterministic detector agree the *visual* layer reads intentional: restrained single indigo, warm-gray OKLCH neutrals (chroma deliberately tiny), two first-class themes, serif "paper" minutes that stay light in dark mode. Detector: 2 warnings only — `single-font`@minutes.html:130 (FALSE POSITIVE: Hanken Grotesk + Source Serif 4 genuinely paired via `.doc`), `flat-type-hierarchy`@present.html:12 (narrow — describes the preflight modal, not the deck). No gradient text, side-stripes, glass, hero-metrics, or eyebrow scaffolding.

The tells are in the **interaction layer**, not the pixels: native `prompt()`/`confirm()`/`alert()` for core actions collapse the premium register the instant they fire.

## What's Working
1. OKLCH token system + two-theme discipline; serif paper minutes staying light in dark mode (product-specific, not template).
2. Ambient status as a system — autosave state machine + readiness bar that answers "is everyone in yet?" at a glance and rewards completion by turning green.
3. Present preflight checklist — curate exactly what goes live, smart all-checked default, real keyboard nav.

## Priority Issues
- **[P0] Native prompt/confirm/alert + raw error dumps** for add/rename/delete team, invites, archive (admin.html:389–407; team.html:347,354). Collapses register + leaks DB internals. Fix: in-app modals/inline forms + toast system + friendly error map. → /harden (+ /clarify)
- **[P1] "Print / Save PDF" silently finalizes and archives the meeting** (minutes.html:160–166). Hidden destructive side effect behind an innocuous label. Fix: split "Save PDF" from "Finalize & archive"; confirm + success state; reversible archive. → /harden (+ /clarify)
- **[P1] No loading / empty-first-run / error states.** Async IIFEs have no try/catch; 0-team admin shows empty table + empty readiness bar; markdown-it CDN failure blanks the page. Fix: skeletons, empty states, global error boundary. → /onboard + /harden
- **[P2] Drawer has no focus management; table rows not keyboard-operable** (admin.html:153,320–330,369–382). Focus not moved/trapped/restored; clickable `<tr>` unfocusable. Fix: role="dialog"+focus trap; route row action through a real button. → /harden
- **[P2] Two divergent markdown renderers** — hand-rolled regex in team.html vs markdown-it everywhere else; a note renders differently where authored vs reviewed/presented. Fix: use markdown-it in team.html (deletion, not addition). → /distill

## Persona Red Flags
**Alex (power user):** every admin action mouse-only; meeting-tab switch does full `location.reload()` (loses scroll); teams table has no sort/filter/search/bulk; row-click and "View" are redundant.
**Sam (a11y/keyboard/SR):** drawer no focus trap/restore; non-focusable rows; readiness bar has no role="progressbar"/aria-live; Present slide changes not announced; autosave/submission not in aria-live regions.

## Minor Observations
CDN fragility (markdown-it failure kills the page, no fallback); `.userchip`/`.avatar` styled but never rendered (no visible signed-in identity); Present preflight card uses `system-ui`, breaking the type system on that one surface; N+1 tab-count queries on admin load.

## Questions to Consider
1. Is *exporting* really the same intent as *finishing*? Print silently archives — what happens the first time an admin just wants a draft PDF?
2. The readiness bar counts pre-meeting prep, not the notes that feed the minutes. Is it measuring the right readiness?
3. VIP mode is team.html in an iframe with postMessage/setTimeout hacks — is it a real experience or an admin cosplaying as a team? Would a purpose-built solo surface be *less* code?
